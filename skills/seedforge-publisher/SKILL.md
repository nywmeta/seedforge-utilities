description: Research, build, test and publish small free Seedforge utilities with evidence, minimal maintenance and an optional verified support link. Use for the Seedforge utility pipeline, not unrelated income assets.

Read `STATUS.md` and `PIPELINE.md` from the Seedforge repository root (two levels above this skill directory). Inspect only records needed for the next useful action. They capture scope, current evidence, access blockers and the €0 external-spend constraint.

Finish an active release or reproduce a reported bug before starting another build. For new candidates, verify real recurring problem reports and current free alternatives, including store publication and recent issue replies. Prefer a small upstream contribution when it avoids owning another utility. Record source dates, checked dates, uncertainty and the selection decision; never equate interest with adoption or revenue.

Build local, bounded tools where possible. Use meaningful behavior checks and the repository release gate. Separate simulation from installed-browser and hardware validation. When distributing hardware-dependent work without device evidence, label it a release candidate and preserve the limitations prominently.

The user has authorized free open-source utility publication to appropriate channels such as GitHub. Handle routine implementation and preparation autonomously. Ask only when access, identity, legal acceptance, security permissions or another necessary confirmation requires the user. Prepare a concrete reviewable result first. Do not infer authorization to send community messages: check exact channel rules and obtain specific authorization before outreach.

Only enable owner-confirmed support URLs after checking the public recipient page. Keep software fully free. Never create a payment identity or claim receipts without evidence. The recipient and payment-account setup are the user's responsibility when confirmation or account terms are involved.

Publication requires reading the resulting live repository/release and recording actual URLs, commit/tag, asset availability and verification time in `publication.json` and `STATUS.md`. A local artifact or attempted upload is not live. If access is unchanged, checkpoint once and stop retrying it. Continue independent useful work without repeated empty progress reports. Stay within existing allowance and free services; no purchased credits, paid runners, advertising or infrastructure.
